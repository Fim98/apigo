### 1.2 Interpolation

- Algorithm in `packages/bruno-common/src/interpolate/index.ts:73-139`: regex `/\{\{([^}]+)\}\}/g`, lodash `get` for dot paths, recursive re-expansion while matches remain, cycle guard via `visited`, per-string memo `results` keyed by the **original match** (so `{{$randomInt}}` used twice in one interpolation call yields the _same_ value), objects JSON-stringified, JSON escaping via `escapeJSONStrings`.
- Dynamic vars are substituted **before** variable lookup (`prepareMock`, `:34-46`) — `{{$guid}}` etc. never collide with user variables.
- Call sites and per-field rules: `packages/bruno-electron/src/ipc/network/interpolate-vars.js:90-241` — URL, header names **and** values, path params (incl. OData `Func(:param)` form), proxy fields, basic auth, OAuth1/OAuth2/AWS/digest/WSSE/NTLM/EdgeGrid config, JSON bodies (whole-object stringify→interpolate→parse), form-urlencoded values, multipart values (string or array), GraphQL query + variables with JSON escaping, gRPC whole body, WS message bodies. Binary bodies (Buffer/stream) are **excluded** from interpolation (`:140`, `isBinaryRequestBody` at `utils/common.js:162`).

### 1.3 Inherited settings

- Merge order: collection root → folders (depth first) → request, for headers, scripts, vars and auth (`prepare-request.js:396-405` calling `utils/collection.js` `mergeHeaders`, `mergeScripts`, `mergeVars`, `mergeAuth`).
- Header merge keyed by name in a `Map`, last wins; disabled headers kept separately when `includeDisabledHeaders` (`utils/collection.js`, CLI copy at `bruno-cli/src/utils/collection.js:99-141`).
- `auth.mode === 'inherit'` resolves to collection auth, but a folder auth with a concrete mode overrides it (`bruno-cli/src/utils/collection.js:513-531`).
- Settings type: `packages/bruno-schema-types/src/collection/item.ts:15-21` — `encodeUrl`, `followRedirects`, `maxRedirects`, `timeout: number | 'inherit'`, `forwardAuthorizationHeader`, `omitHeaders: string[]`.
- Desktop resolves `timeout === 'inherit' | undefined | null` to the app preference `preferencesUtil.getRequestTimeout()`, whose default is **0 = no timeout** (`utils/collection.js:927-951`; `store/preferences.js:419-421`). CLI does **not** resolve `'inherit'`: it only applies a numeric `settings.timeout > 0` (`runner/run-single-request.js:683-686`), so `timeout: inherit` also means _no timeout_ in CLI, but via a different rule (`'inherit' > 0` is false).

### 1.4 Redirects

- Client-side redirect loop with `maxRedirects` default **5** (`DEFAULT_MAX_REDIRECTS`, `bruno-common/src/utils/index.ts:100`); `followRedirects: false` forces `maxRedirects = 0` (`ipc/network/index.js:146-164`).
- Handled in the axios response error interceptor: 301/302/303 rewrite to `GET`, drop body + `content-length` + `content-type` (except `HEAD`); 307/308 preserve method and body; consumed `form-data` is rebuilt from `_originalMultipartData` (`ipc/network/axios-instance.js:451-506`).
- Cross-origin: `x-amz-*` always stripped and SigV4 re-sign disabled (`__skipAwsV4Sign`); `Authorization`/`Proxy-Authorization` stripped unless `forwardAuthorizationHeader` (default true) (`:423-449`). Relative `Location` resolved against the current URL (`:396-406`). Cookies re-read for the redirect target (`:508-513`). NTLM: `x-retry` + `Authorization` dropped, custom adapter removed to renegotiate (`bruno-requests/src/auth/ntlm.ts:14-41`).
- CLI has the same logic in `bruno-cli/src/utils/axios-instance.js:32-245` (no per-hop timeline, no FormData logging).

### 1.5 TLS

- `rejectUnauthorized: false` when the app preference disables TLS verification (`cert-utils.js:28-30`); CLI `--insecure` (`runner/run-single-request.js:407-414`).
- CA bundle = OS system CAs (`tls.getCACertificates('system')`) + Node root CAs + custom `--cacert` file + `NODE_EXTRA_CA_CERTS`, de-duplicated, joined with `\n` (`bruno-requests/src/utils/ca-cert.ts:21-160`). `--ignore-truststore` drops system+root when a custom CA is given.
- Client certificates: per-collection `brunoConfig.clientCertificates.certs[]`, matched by `domain` glob → regex `^(https://|grpc://|grpcs://|ws://|wss://)?<glob>`; `type: 'cert'` reads cert+key files, `type: 'pfx'` reads pfx; both take `passphrase`; first match wins (`cert-utils.js:69-111`). Desktop also merges app-level global certs (`preferencesUtil.getGlobalClientCertificates()`).
- Agents: `keepAlive: true` by default (issue #211), `minVersion: 'TLSv1'`, optional SSL session caching (`--cache-ssl-session` → per-host agent cache, `utils/agent-cache.ts`).
- Client certs / `rejectUnauthorized` are forwarded through the HTTPS **proxy** agent via `PatchedHttpsProxyAgent` (`bruno-requests/src/utils/http-https-agents.ts:209-241`).

### 1.7 DNS

- Only localhost special-casing exists (`ipc/network/axios-instance.js:184-206`): `127.0.0.1` forced IPv4 lookup, `::1` forced IPv6, any `*.localhost` probes IPv6 then IPv4 on the request port with a cached `net.Socket` connect check; all other hosts use Node's default resolver. No DNS-over-HTTPS, no custom resolver settings, no `/etc/hosts` override beyond Node defaults. **[absent]** otherwise.

### 1.8 Cookies

- Single module-level `tough-cookie` `CookieJar` (`bruno-requests/src/cookies/index.ts:6`). Helpers: `addCookieToJar` (loose parse, `__Host-` prefix handling), `getCookieStringForUrl` (drops expired), `getDomainsWithCookies`, CRUD for the cookie UI (`:13-184`).
- Desktop honours preferences `shouldStoreCookies` / `shouldSendCookies` and persists the jar (`ipc/network/index.js:54-68`, `:343-371`; jar file via `store/cookies.js` + `cookiesStore.saveCookieJar()`).
- Cookie header merging: existing `Cookie` header parsed into name→value, jar values override on collision, rejoined (`:352-369`).
- CLI: jar always active unless `--disable-cookies`; **no persistence across runs** (`bruno-cli/src/utils/cookies.js` + `run-single-request.js:508-536`).

### 1.9 Compression

No first-party compression code. Defaults come from axios (`Accept: application/json, text/plain, */*`, `Accept-Encoding: gzip, compress, deflate, br`) as codified in `bruno-common/src/headers/default-headers.ts:13-44`; bruno adds `User-Agent: bruno-runtime/<version>`, Node adds `Host`/`Connection`. Decoding of gzip/deflate/br is delegated to axios/Node and is **not** asserted by Bruno source; behaviour for `responseType: 'stream'` bodies is implementation-defined. **[uncertain]**

### 1.10 HTTP versions

No HTTP/2 or HTTP/3 client for API requests — `axios` over `http`/`https` agents ⇒ HTTP/1.1. The timeline only _reports_ `HTTP/2` if `response.request.res.httpVersion` says so (`ipc/network/axios-instance.js:282-289`). gRPC uses HTTP/2 internally via `@grpc/grpc-js`. HTTP/2 API requests: **[absent]**.

### 1.11 Streaming

- SSE only, keyed on `content-type: text/event-stream` (`hasStreamHeaders`, `ipc/network/index.js:82-85`). The raw stream is handed to the renderer chunk-by-chunk (`main:http-stream-new-data`), chunks accumulate in `sseChunks`, and on `close` the full body is rebuilt and post-response scripts/assertions/tests run (`:1286-1309`).
- Everything else is fully buffered (`promisifyStream` `:93-117`). Download-to-disk streaming: **[absent]** (only upload streaming for files > 20 MiB, `prepare-request.js:10`, `:484-490`).
- CLI: no streaming at all; SSE responses are buffered by axios.

### 1.12 Cancellation

- `AbortController` per request; `cancelTokens[uuid] = abortController` (`utils/cancel-token.js`), `cancel-http-request` IPC aborts (`:1441-1452`).
- Cancelled request returns `{statusText: 'REQUEST_CANCELLED', isCancel: true, error, timeline}` instead of rejecting (`:1089-1098`).
- Runner cancellation: outer abort listener aborts the in-flight request; the `--delay` wait is raced against the abort signal (`:1478-1482`, `:1898-1908`).
- CLI: `runAbortController` in `commands/run.js:775-785`, propagated as `request.signal` (`run-single-request.js:743-745`), aborted by `--bail` or `bru.runner.stopExecution()`.

### 1.13 Timing / timeline

`performance.now()`-based hop accounting (`bruno-requests/src/network/response-time.ts:1-42`): each hop records `Request completed in N ms`, response-header arrival, preparation time. Timeline entries are typed `separator|info|request|requestData|requestHeader|response|responseHeader|timing|error` (`ipc/network/axios-instance.js:150-312`). `duration` = sum of completed hops (+ open hop for streamed bodies).

### 4.1 Engines and selection

### 4.3 Script phases and merge order

- Pre-request: `request.script.req`; post-response: `request.script.res`; tests: `request.tests` (a string body, `.bru` `tests { }` block).
- `scriptFlow` from `brunoConfig.scripts.flow` (default `sandwich`):
  - `sandwich`: pre-request = collection → folders → request; post-response and tests = request → folders (reversed) → collection.
  - `sequential`: collection → folders → request for all three.
    (`bruno-cli/src/utils/collection.js:381-443`; desktop equivalent uses the same merge helpers.)
- Scripts are comment-stripped with `decomment(script, {space:true})` before execution (`ipc/network/index.js:612`, `:740`, `:1228`).
- Post-response variables (`.bru` `vars:post-response`) run **before** the post-response script, as JS expressions with `bru`, `req`, `res` in scope; each expression's value is `bru.setVar(name, value)`; errors are aggregated into one message (`vars-runtime.js:28-97`).

### 4.4 Async semantics

- Script body is awaited in both sandboxes. QuickJS waits `waitForPendingDeferreds()` (unbounded; cancel is the escape hatch) — `quickjs/index.js:212-229`.
- `test()` promises are tracked per phase and awaited after the script finishes, including `test()` calls made inside another `test()` callback (`bruno-js/src/utils/results.js:28-56`).
- nodevm also awaits pending tests and re-binds `req.onFail` callbacks under `--experimental-cache-modules` (`sandbox/node-vm/index.js:76-89`).

### 4.5 Error handling

- Any thrown error is wrapped (`ScriptError`) and re-thrown with `error.partialResults` attached: the full result object built so far (variables, tests, `nextRequestName`, `skipRequest`, `stopExecution`, scripted request entries) (`script-runtime.js:139-145`, `:160-166`; `test-runtime.js:148-153`).
- Callers append a synthetic fail row: `{status:'fail', description:'<Pre-Request|Post-Response|Test> Script Error', error, isScriptError:true}` (`ipc/network/index.js:504-535`; CLI `run-single-request.js:879-901`, `:955-981`).
- Pre-request script errors **abort** the request (desktop rejects before sending `:999-1001`; CLI returns early with `status:'error'` `:345-375`). Post-response/test errors do **not** stop the run.
- QuickJS traps/WASM aborts during teardown recycle the engine module and do not fail the run (`quickjs/index.js:66-82`).
- Stack traces are mapped back to `.bru`/`.yml` source lines by `formatErrorWithContextV2` (`bruno-js/src/utils/error-formatter.js`), using `reqMetadata`/`resMetadata`/`testsMetadata` computed during script merging.

| Capability                                                                                                          | Reality in Bruno                                                                                      | Go options                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |

## 5. Assertions and tests

### 5.1 `.bru` assertion syntax

```bru
assert {
  res.status: eq 200
  res.body.id: isNumber
  res.body.name: eq "Bruno"
  res.body.items: isArray
}
```

Parsed from the `assert` dictionary block (grammar `packages/bruno-lang/v2/src/bruToJson.js:103-110` for the pair grammar, `:148` for `assert = "assert" assertdictionary`). Each row is `{name, value, enabled}`; `name` = lhs JS expression, `value` = `<operator> <operand>`.

### 5.2 Operators

`packages/bruno-js/src/runtime/assert-runtime.js:235-310` — default operator `eq` when the token is unknown. Mapping to chai (`:471-560`):

| Operator                                                | chai                                                            |
| ------------------------------------------------------- | --------------------------------------------------------------- |
| `eq` / `neq`                                            | `equal` / `not.equal`                                           |
| `gt` `gte` `lt` `lte`                                   | `greaterThan` `greaterThanOrEqual` `lessThan` `lessThanOrEqual` |
| `in` / `notIn`                                          | `oneOf` (operand comma list, `[a, b]` tolerated)                |
| `contains` / `notContains`                              | `include` / `not.include`                                       |
| `length`                                                | `lengthOf`                                                      |
| `matches` / `notMatches`                                | `match new RegExp(op)` (leading/trailing `/` stripped)          |
| `startsWith` / `endsWith`                               | `startWith` / `endWith` (chai-string)                           |
| `between`                                               | `within(min,max)` (comma list)                                  |
| `isEmpty` `isNotEmpty`                                  | `empty` / `not.empty`                                           |
| `isNull` `isUndefined` `isDefined` `isTruthy` `isFalsy` | `null`, `undefined`, `not.undefined`, `true`, `false`           |
| `isJson`                                                | custom property `json` (`Array` or `[object Object]`)           |
| `isNumber` `isString` `isBoolean` `isArray`             | `a('number'                                                     | 'string' | 'boolean' | 'array')` |

- Unary operators ignore the operand (`:274-287`, `:355-358`).
- Evaluation: lhs is a JS **expression**; rhs is interpolated then evaluated as a **template literal** (`${...}`) — so `eq {{token}}`, `eq 'foo'`, `eq 123`, `eq true`, `eq null`, `eq undefined` all behave as literal-typed values (`:331-403`). QuickJS uses `executeQuickJsVm({scriptType:'template-literal'})` with number/bool/null short-circuits (`quickjs/index.js:96-162`), nodevm uses `evaluateJsTemplateLiteral`.
- Context for evaluation: all variable scopes flattened **plus** `bru`, `req`, `res` (`:441-457`). Process-env **entries are spread as bare globals** (last `...processEnvVars` at `:456`) and there is no `process` object in the QuickJS assert context — so `PATH` is reachable as an identifier, `process.env.PATH` is not. The nodevm assert path is looser: expressions are compiled with `new Function` in the host realm and only the identifiers they mention are destructured from the context, with a `globalThis` fallback (`utils.js:26-63`) — so `process.env.PATH` works there but not in safe mode. (The same flattening means a variable named like a JS built-in shadows it inside assertion expressions.)
- Result rows: `{uid: nanoid(), lhsExpr, rhsExpr, rhsOperand, operator, status: 'pass'|'fail', error}`; failures record `err.message` only (`:562-580`). No retry, no soft-assert.
- Disabled assertions are skipped; an empty enabled set returns `[]`.

### 5.3 `test()` semantics

`packages/bruno-js/src/test.js:1-27` + `utils/results.js:28-56`:

- `test(description, callback)` is async; `await callback()` ⇒ `status:'pass'`; thrown error ⇒ `status:'fail'` with `error.message`, and for chai `AssertionError` also `actual`, `expected`, `stack`, `errorName`.
- All `test()` promises per phase are awaited (§4.4). A failing test does not abort the script.
- Available in pre-request, post-response and tests phases; results are reported per phase (pre-request/post-response/test) and counted separately in summaries.
- `expect`/`assert` are chai 4. Custom assertion extensions registered globally in `assert-runtime.js:14-201`: `chai-string` (startWith/endWith), `json`, `jsonSchema` (ajv draft-07 only; any other `$schema` fails with an explicit message; `ajvOptions` override supported), `match`, `jsonBody(path?, value?)` with Postman-style path parsing (`a.b`, `a[0]`, `a["b.c"]`).

### 5.4 Reporting and exit status

- CLI prints one line per request (`path (status statusText) - N ms`), then per-phase result lists with `✓`/`✕`, stack excerpts for script failures (`run-single-request.js:145-173`, `:814-820`), a cli-table3 summary (`Metric|Result`: Status, Requests, Tests, Assertions, Duration) (`commands/run.js:49-82`), and `Ran all requests - N ms`.
- Summary math: `bruno-common/src/runner/runner-summary.ts:4-113`. A request counts as passed only if no assertion/test/pre/post test failed and `status !== 'error'`; script-error rows set `anyFailed` but are excluded from test counts; skipped requests are counted separately (with `skipReason === 'bail'` tracked).
- Exit code is **1** if `failedAssertions + failedTests + failedPreRequestTests + failedPostResponseTests + failedRequests > 0` or `errorRequests > 0` (`commands/run.js:993-995`).

## 6. Runner semantics

### 6.1 Selection and ordering (CLI)

- `bru run [paths...]`; no paths ⇒ `./` with `recursive = true` (`commands/run.js:679-682`).
- Collection tree built by walking the directory, skipping `environments/`, `.git`, `node_modules`; folders sorted by `name` then `seq`, requests sorted by `seq` (`bruno-cli/src/utils/collection.js:55-96`; `sortByNameThenSequence` in `bruno-common/src/collection`).
- `-r/--recursive` controls whether a folder target expands recursively; a file target contributes exactly itself (`getCallStack`, `utils/collection.js:554-584`).
- `--tests-only`: keeps requests whose `tests` block, pre-request or post-response script contains a standalone `test(` call (comment/string-stripping heuristic, `utils/request.js:1-44`) or with ≥1 enabled assertion.
- `--tags` / `--exclude-tags` (comma-separated): effective tags = own + inherited folder tags; include = OR over include list; exclude wins (`tags/index.ts:92-96`, `run.js:711-716`).
- Desktop runner additionally accepts explicit `selectedRequestUids` ("Configure requests to run") and preserves that order (`ipc/network/index.js:1625-1639`).
- Transient requests are skipped; gRPC requests are **skipped** in desktop folder runs with a `runner-request-skipped` event (`:1686-1702`). WS requests are also skipped (same branch logic).
- Requests containing prompt variables (`{{?Name}}`) are skipped in both runners with a skip reason (`:1707-1726`; CLI `run-single-request.js:188-220`).

### 6.3 Environments

- CLI environment sources, in order: `--env-file` (`.bru`/`.json`/`.yml`, extends chain intentionally **not** resolved) → collection `bruno.json` `presets.defaultEnvironment` (only bare filenames accepted) → `--env <name>` (`environments/<name>.<ext>`), with `--env` merged over `--env-file` (`run.js:400-484`).
- Environment inheritance: `extends` (string or list) resolved root-ancestor-first; secrets and non-secrets merged separately so a secret always wins over a plain var of the same name; cycles and missing parents reported (`bruno-common/src/utils/environment-inheritance.ts:60-206`; secret-wins flattening `environment-variables.ts:10-31`).
- `--global-env <name>` requires a `workspace.yml` in an ancestor (or `--workspace-path`), loads `<workspace>/environments/<name>.yml` (`run.js:486-541`); errors 11/12/13.
- `--env-var NAME=VALUE` / `--global-env-var NAME=VALUE` repeatable; overrides are tracked so the persistence layer can distinguish a leaked override from a script write (`run.js:543-595`).
- Variable mutations made by scripts are persisted back to the env/collection files after each request (`utils/persist-variables.js`), preserving `dataType`, marking secrets and blanking their on-disk value, and skipping overrides that were only injected.

### 8.3 Prompt variables

`{{?Prompt Text}}` — pattern `/\{\{\?([^{}\s](?:[^{}]*[^{}\s])?)\}\}/g` (`bruno-common/src/utils/prompt-variables.ts:21-33`). Extraction walks the whole prepared request plus every variable scope plus cert/proxy config (`ipc/network/index.js:1350-1384`). Both runners refuse to execute such requests: desktop emits a skip (`:1707-1726`), CLI returns `status:'skipped'` (`run-single-request.js:188-220`). Only the interactive app prompts the user and then passes `collection.promptVariables` into interpolation.

### 8.4 Secrets

- Env vars carry `secret: boolean`. Secrets are never serialized with a value: `.bru`/`.yml` writers emit name-only rows and the CLI's persistence marks them `secret: true` with `value: ''` (`bruno-cli/src/utils/persist-variables.js:38-56`).
- Desktop keeps secret values in a separate encrypted `electron-store` (`bruno-electron/src/store/env-secrets.js:1-90`, `utils/encryption.js`).
- Consequence: a CLI run reads secret variables as empty unless injected via `--env-var` (the documented CI pattern, `commands/run.js:383-390`) or supplied in `--env-file`/`.env`.
- Reporter redaction is **explicit only** (headers/bodies via `--reporter-skip-*`); there is no automatic secret masking in results.

### 8.5 Typed variables

`dataType: 'string'|'number'|'boolean'|'object'` (`bruno-common/src/utils/datatype.ts`), coerced by `parseValueByDataType`: a whole-string `{{var}}` reference returns the referenced value uncoerced; `number`/`boolean`/`object` (JSON) conversion otherwise; failures fall back to raw. Persistence infers `dataType` from the JS type and omits `string` (`persist-variables.js:24-36`). CLI integration test: `packages/bruno-cli/tests/integration/run-typed-persistence.spec.js`.

### 8.6 Unresolved variables

Collected per prepared request (`WeakMap`) via an `onUnresolved` callback threaded through interpolation and `bru` reads; surfaced to the renderer as `unresolved-variables` events, never failing a request (`bruno-js/src/unresolved-variables.js`, `ipc/network/index.js:899-915`).

## 11. Cross-cutting notes for a Go reimplementation

1. **Two code paths must be modelled.** Desktop semantics (preferences-backed TLS/proxy/cookies, interactive OAuth2, SSE) differ from CLI semantics (flags, no persistence, no streaming). Pick CLI semantics as the baseline for a test runner, and add desktop-only features behind explicit config.
2. **Send-time header truth.** What Bruno reports as sent headers is parsed from Node's `ClientRequest._header` _after_ the socket write (`sent-headers.ts`), then merged back into `request.headers` for post-response scripts (`applySentHeadersToRequest`). A Go engine must decide whether `req.headers` in post-response scripts includes transport defaults (`User-Agent`, `Accept`, `Accept-Encoding`, `Host`, `Connection`) — Bruno does.
3. **Header omission** is a three-way interaction: `settings.omitHeaders`, script `req.deleteHeader`, and explicit user headers; `Host` can never be omitted; `Connection` requires agent `keepAlive:false` (`default-headers.ts:99-144`).
4. **`content-type: false`** is a sentinel to suppress axios defaults for `body.mode: none`; it must not be sent nor reported.
5. **Multipart replay on 307/308** needs the original part list retained (`_originalMultipartData`) because a `form-data` stream is single-use.
6. **Deterministic ordering** everywhere: folders by name then `seq`, requests by `seq`, headers by insertion, variables by merge order, tests/assertions in file order.
7. **WSSE digest quirk** (§2) must be reproduced exactly if parity with Bruno servers is required, otherwise documented as a deliberate fix.
8. **Easter egg**: `WOOF` method returns `easterEggResponse` (`utils/woof.js`); safe to omit.
